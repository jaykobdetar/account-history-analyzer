# AHAS 1.0.1: pinned ruptures PR #383 integration

This is a focused optimizer update requested by the user. The attached audit and its broader repair prompt supplied context; this patch does not claim to repair AHAS-AUD-001–004. Scientific real-world validation remains unestablished.

## Source and implementation

The upstream PR was open, not merged, when retrieved. The exact source is [commit a28574d9e63b0c2a966e176a1d049d3c9deaaaaf](https://github.com/deepcharles/ruptures/commit/a28574d9e63b0c2a966e176a1d049d3c9deaaaaf), based on `ee1c8ff8a548d54c641b2bb471562165931f31c7`. The public retrieval receipt and patch are under `qa/pr383/`.

- `src/account_history_analyzer/_vendor/ruptures_pr383.py` contains the verbatim `Pelt._seg` method in a private subclass. Its only local scaffolding is the import/class/documentation. It does not monkeypatch the installed library.
- `ruptures_pr383_source.txt`, `ruptures_pr383.json` and `ruptures_LICENSE.txt` alongside it retain full source bytes, SHA-256 identities, commit provenance and the complete BSD-2-Clause notice. They are included in the wheel and implementation fingerprint.
- `changepoints.py` validates finite inputs, catches numerical overflow, invokes the backport with explicit L2/min_size/jump settings, and independently exports segment SSE plus beta times the number of **internal** boundaries. The upstream per-segment penalty convention differs by a constant beta.
- The old AHAS optimizer is removed from production. The PR's strict comparisons, full-partition accumulation, feasible-start admission, sample-coordinate pruning deadlines and first-candidate tie order are unchanged. Near ties may resolve differently from the original AHAS scalar recurrence and conservative pruning slack.
- Existing family scaling, window/sample guards, uncalibrated penalties, boundary-to-source mapping and sensitivity definitions are retained. No IDs, labels, truth sidecars or fixture names enter optimizer coordinates.

The frozen dependency versions and hash locks are unchanged; only AHAS's version in `uv.lock` changes. A narrow source backport avoids installing unrelated development-branch changes or a floating Git dependency. No additional runtime download or service is introduced.

Suite version, registry version, report-template version and the `pelt_l2_v1` method version are 1.0.1. The new optimizer identifier is `ruptures_pelt_pr383_a28574d_v1`. Other method versions and the 1.0.0 data format remain unchanged. The result schema accepts both old and new optimizer identifiers for historical readability; current analyses emit only the new one. The method registry names the exact upstream commit and integration. Boundary finding envelopes carry the new PELT method version.

## Measured optimizer performance

The archived 1.0.0 optimizer and new wrapper used the same pinned CostL2 on ten bounded inputs: the frozen 29×31 style matrix and deterministic 128/256×8 stationary/step arrays, each at minimum segment lengths 3 and 20. Each variant/workload ran in a fresh process, with one warmup, five untraced timing repetitions and five separate allocation repetitions. All boundaries matched and all exported objectives were exactly equal on these inputs.

On the actual style matrix with minimum 3, median runtime was **1.945 ms before / 2.042 ms after**, and traced peak per-call allocations were **14.6 / 23.4 KiB**. Across these workloads the new/old runtime ratio was **0.964–1.052**, with traced peak-allocation ratio **1.138–3.542**. These measurements describe this host and these bounded arrays; they are not an asymptotic or maximum-history claim. Full partition dictionaries explain additional retained state. Process-wide RSS includes imports/warmups and must not be interpreted as per-call optimizer memory. Raw values, arrays and separate operational receipts are in `qa/pr383/benchmark/`.
