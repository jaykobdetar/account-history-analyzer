# Review decisions, changes and open issues

Reviewed 2026-09-15. **Adopt 0.1.1 locally as the evidence destination contract.** It remains a draft; do not reinterpret or automatically upgrade 0.1.0 rows. Engine 1.0.4 and input schema 1.0.0 remain frozen. No new required bundle files or ontology modules were added: minimum is still manifest + records JSONL.

The historical package is unchanged. New schemas/examples were rebuilt from explicitly revised builders; version/hash-domain/normalizer identity changes produce new hashes, including source-local IDs. These are new fixtures, not repaired historical receipts.

## Exact supported contracts

- **Supported locally:** strict version-selected AHIF 0.1.1 evidence syntax, documented semantic/integrity rules, small offline directory-bundle validation, optional canonical-export check, deterministic fictional fixture/schema generation. Same logical keys can have multiple observations; no winner chosen. Unknown actor/time/language/scope and absent raw evidence are valid.
- **Historical only:** 0.1.0 package/examples/checker/receipts. Its checker can be rerun separately as historical evidence. The 0.1.1 checker refuses 0.1.0 versions; no transparent migration is supplied.
- **Unchanged existing contract:** production AHAS 1.0.4 consumes its own record/snapshot schema 1.0.0. AHIF data is not drop-in input; the optional extra `accounts.jsonl` never adds timeline events.
- **Not supported by this work:** data acquisition, source normalizers, AHAS conversion/receipt implementation, merges/reconciliation, database or archive ingestion, source verification, language identification, neural models, publishing, real-account scientific evaluation, platform-transfer claims, legal/consent/license determinations or completeness estimation.

## Open issues deliberately left for named future work

1. **First source profile:** fix namespace/collection spellings, native ID aliases, exact raw locators, native action/type semantics, markup boundaries and declared transformations for one permitted source. No need to predefine every platform now.
2. **Selection and projection:** version the receipt schema, resolve or refuse edits/conflicts, preserve handle/source-local scope, implement the map and test frozen output behavior. Define exclusion accounting before claiming posting counts.
3. **Source evidence and retention:** source-specific fidelity/verification and privacy/withdrawal procedures remain outside schema validation. Hashes and access labels are not proof, consent or licenses.
4. **Production ingestion:** streaming, bounded decompression, race-resistant file handling, directory enumeration budgets, full hostile-ingestion review and operational resource measurements require separate implementation. Current limits are fixture operating limits, not a security/service guarantee.
5. **Language and URI profiles:** tag registry/grandfathered forms, provider authority aliases and same-entity reconciliation need explicit profiles only if real input requires them. Unknown remains a valid alternative.
6. **Cross-language canonical conformance:** fixed restricted-domain Python/Node comparison is a bounded check; no full RFC 8785 suite or general float/non-ASCII-property JCS implementation is claimed.

These issues do not prevent storage of the required examples. Additional mandatory modules/files need a concrete record that the current structure cannot represent.
